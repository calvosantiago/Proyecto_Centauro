1. Qué Es Centauro

Centauro es un sistema de evaluación automatizada de llamadas comerciales (educación) que analiza conversaciones, etiqueta interlocutores, evalúa bloques consultivos y genera feedback accionable con evidencia literal.

1.1 Objetivo Operativo

  • Evaluar calidad comercial por bloques específicos.
  • Reducir alucinaciones del LLM con validación de evidencias (Sheriff).
  • Aportar recomendaciones accionables apoyadas en manuales, buenas prácticas y coaching.
  • Permitir operación tanto por lotes/CLI como por interfaz interactiva (Chainlit).

1.2 Modos de Uso

  • Modo evaluación (archivo): procesamiento end-to-end de una llamada y generación de JSON/PDF.
  • Modo chat interactivo: preguntas al conocimiento RAG y a memoria de asesores.
  • Modo CLI batch: proceso de múltiples transcripciones desde inputs/transcripts.

3. Entradas, Preproceso Y Flujos (Texto, Audio, Video)

3.1 Entradas soportadas en evaluación

  • .txt
  • .vtt
  • .docx

Validaciones en centauro/utils/validaciones.py:

  • Extensión permitida.
  • Archivo existente y no vacío.
  • Límite de nombre y ruta (Windows), configurable en centauro/config.py.

3.2 Flujo audio

  1. Colocar mp3 en inputs/audios.
  2. Ejecutar python centauro/tools/whisper_transcribe.py.
  3. Salida en inputs/transcripts/*_whisper.txt.
  4. Procesar luego con main.py o por Chainlit.
Detalle: la transcripción Whisper se guarda sin speaker tags para que la diarización posterior sea contextual por LLM.

3.3 Flujo video

  1. Colocar videos en inputs/videollamadas.
  2. Ejecutar python centauro/tools/extract_audio.py (requiere C:\ffmpeg\bin\ffmpeg.exe).
  3. Se generan MP3 en inputs/audios.
  4. Ejecutar Whisper para pasar a transcripción y continuar flujo normal.

3.4 Privacidad y RGPD

Antes de diarizar/evaluar, redact_pii() reemplaza PII por marcadores [REDACTED_*]:

  • Email
  • Teléfono
  • DNI / NIE
  • IBAN español

4. Diarización: Cómo Separa ASESOR Y LEAD

DiarizationAgent resuelve múltiples formatos y aplica estrategia “contenido primero”.

4.1 Detección automática de formato

  • Word pre-diarizado: [NOMBRE]: texto.
  • Formato Teams timestamp: Nombre HH:MM texto.
  • VTT con speakers: <v NOMBRE>texto</v>.
  • VTT con UUIDs.
  • Texto plano sin estructura.

4.2 Asignación de roles

  • Calcula score semántico de asesor/lead por anclas de contenido.
  • Usa coincidencia de nombre solo como respaldo, no como regla principal.
  • Fallback heurístico si el LLM falla o el formato no es concluyente.

4.3 Caso especial VTT UUID

  • Si pocos UUID repetidos: trata UUID como speaker.
  • Si UUID secuencial masivo: diarización batch LLM por chunks con overlap.

4.4 Salida de diarización

Formato normalizado:

[ASESOR]: ...

[LEAD]: ...

Se guarda además copia debug en outputs/Input_Debug/*_diarizada.txt.

6. RAG: Teoría + Implementación En Centauro

6.1 Qué es RAG (contexto teórico)

RAG (Retrieval-Augmented Generation) combina:

  • Retrieval: recuperar conocimiento relevante de una base documental.
  • Generation: usar ese contexto para guiar respuestas/evaluaciones del LLM.

Beneficios clave en Centauro:

  • Reduce respuestas genéricas.
  • Ancla recomendaciones en material interno (manuales, ejemplos, coaching).
  • Mejora consistencia y trazabilidad.

6.2 Base vectorial y colecciones

RAG opera sobre ChromaDB persistente (chroma_db/) con embedding text-embedding-3-small.

ColecciónUsoOrigen
manuales_generalesGuías base de ventainputs/docs/*.txt
buenas_practicasEjemplos reales por bloqueinputs/docs/buenas_practicas/*
coaching_ventasTécnicas de libros/mentoresinputs/docs/coaching_ventas/*.txt
evaluaciones_historicasAprendizaje desde llamadas buenasMemoria continua
dossiers_programasContexto específico de programasoutputs/dossiers_procesados/*.txt

6.3 Indexación documental

Función principal: indexar_documentacion(). Ejecuta:

  1. Manuales generales (chunking configurable).
  2. Buenas prácticas por sección (indexación completa por ejemplo).
  3. Coaching de ventas con chunking semántico.
  4. Dossiers procesados.

6.4 RAG dinámico por bloque

DynamicRAGAgent hace:

  • Extracción de temas de la llamada (muestreo inteligente en llamadas largas).
  • Construcción de query adaptativa según bloque.
  • Recuperación multicolección: manuales + coaching.
  • Filtrado de relevancia y cache de resultados.
flowchart LR A[Transcripción diarizada] --> B[extraer_temas_llamada] B --> C[query dinámica por bloque] C --> D[manuales_generales] C --> E[coaching_ventas] C --> F[buenas_practicas opcional] D --> G[contexto final] E --> G F --> G G --> H[Prompt del agente]

6.5 Parámetros clave (config central)

  • RAG_CHUNK_SIZE=1000
  • RAG_CHUNK_OVERLAP=250
  • RAG_TOP_K_GENERAL=5
  • RAG_TOP_K_BUENAS_PRACTICAS=3
  • RAG_TOP_K_COACHING=2

7. Sheriff Anti-Alucinaciones

_sheriff_validar() valida evidencias citadas por cada bloque contra la transcripción completa.

7.1 Lógica de verificación

  • Valida evidencia principal + extras.
  • Usa fuzzy matching (RapidFuzz) con umbral alto.
  • Calcula porcentaje de evidencias verificables.

7.2 Regla de ajuste de nota

  • Si evidencias verificables < 30%: marca alucinación.
  • Penaliza un nivel de calificación (BUENO→MEJORABLE, MEJORABLE→MALO).
  • Registra metadatos de validación por bloque.

7.3 Telemetría operativa

El orquestador acumula en stats:

  • alucinaciones_detectadas
  • notas_ajustadas_sheriff
  • llamadas_api
  • modo_ejecucion

8.1 Resumen contextual (FASE 2.5)

El sistema extrae de la voz del lead:

  • perfil_lead
  • fase_funnel (AWARENESS, CONSIDERATION, DECISION, CIERRE_INMEDIATO)
  • objetivo_del_lead
  • barreras_principales
  • resultado_general

8.2 Síntesis del reporte

_sintetizar_evaluaciones() consolida:

  • Calificación global por mayoría simple.
  • Feedback resumido con áreas de mejora.
  • Meta técnica (modo batch, distribución de calificaciones, etc.).

9. Chat Interactivo, Memoria Y Aprendizaje Continuo

9.1 Chat Handler (intención + búsqueda)

ChatHandler clasifica intención y enruta a contexto:

  • manual → manuales.
  • ejemplo → buenas prácticas.
  • perfil → perfil histórico de asesor.
  • estadisticas → métricas globales.
  • general → búsqueda multicolección.

9.2 Memoria por asesor

MemoryManager mantiene perfiles en outputs/perfiles_asesores/*.json:

  • Histórico de evaluaciones.
  • Tendencia (mejorando / estable / empeorando).
  • Fortalezas y áreas de mejora consistentes.
  • Rolling window configurable (180 días).

9.3 Aprendizaje hacia RAG histórico

Evaluaciones con nivel mínimo configurado se pueden indexar en evaluaciones_historicas para alimentar ejemplos futuros.

15. Glosario

  • RAG: Retrieval-Augmented Generation; recuperación de contexto documental + generación.
  • Sheriff: validador de evidencias literales anti-alucinación.
  • Diarización: separación de hablantes en roles ASESOR/LEAD.
  • Chunk: fragmento de texto en el que se divide un documento para indexarlo o recuperarlo en RAG.
  • Embedding: representación vectorial numérica del texto, usada para medir similitud semántica en la búsqueda.
  • Observabilidad: grado en que un bloque puede evaluarse con evidencia disponible.
  • Batch híbrido: parte de bloques individual, parte en llamada conjunta optimizada.
  • Coaching: fragmentos de libros/técnicas comerciales para recomendaciones.
