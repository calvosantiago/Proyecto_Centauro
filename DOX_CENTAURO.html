🦄 Proyecto Centauro: Manual Técnico Integral

Versión: 2.1 (Deep Dive API & Prompt) | Última Actualización: Diciembre 2025

1. Resumen de Arquitectura

Centauro es un sistema de auditoría automática basado en RAG (Retrieval-Augmented Generation) y validación determinista. Su objetivo es transformar transcripciones de ventas no estructuradas en reportes de calidad puntuados matemáticamente.

El flujo de datos sigue una estricta política de "Confianza Cero" en la IA generativa, utilizando una capa de código Python ("Sheriff") para validar cada afirmación contra el audio real.

1.1. Flujo End-to-End (Visión Operativa)

El sistema se ejecuta de forma batch y local. El punto de entrada es main.py, que carga manuales, limpia transcripciones y orquesta la auditoría completa.

1.3. Principios de Diseño

  • Determinismo sobre creatividad: Temperatura 0 y JSON estricto.
  • RAG acotado: La IA solo ve fragmentos recuperados, no el manual completo.
  • Auditoría verificable: Cada conclusión debe tener evidencia textual y pasa por el Sheriff.
  • Privacidad: Se aplica redacción de PII antes de enviar a la API.

2. Anatomía del Prompt y Conexión API

El núcleo de la inteligencia de Centauro reside en cómo se comunica con OpenAI. No es un chat simple; es una inyección de contexto estructurada.

2.1. Conexión API (llm_client.py)

Este módulo gestiona el "handshake" con OpenAI. Se ha configurado para eliminar la creatividad y maximizar la precisión analítica.

  • Modelo: gpt-4o-mini (Optimizado para costes y alta velocidad).
  • Temperatura: 0.0.
    Justificación: Necesitamos determinismo. Ante el mismo input, la IA debe dar siempre el mismo output. No queremos "creatividad" en una auditoría.
  • Response Format: { "type": "json_object" }. Forzamos a la IA a devolver exclusivamente JSON válido, evitando texto introductorio.
  • Control de Costes: El script calcula los tokens de entrada/salida y registra el gasto en outputs/control_gastos.csv automáticamente.
  • Embeddings: Se usa text-embedding-3-small para vectorizar manuales y queries.
  • Autenticación: La API key se carga desde .env con python-dotenv (ver centauro/config.py).

2.2. Ingeniería del Prompt (analyze.py)

Utilizamos una estrategia de "Contenedores XML" para separar las instrucciones de los datos, evitando alucinaciones por contaminación de contexto.

graph TD subgraph "System Message (Instrucciones)" A[Rol: Auditor Estricto] B[Reglas Anti-Alucinación] C[JSON Schema Obligatorio] D["MANUAL (Contexto RAG)"] end subgraph "User Message (Datos)" E["AUDIO_REAL (Transcripción Sanitizada)"] end A --> API B --> API C --> API D --> API E --> API[OpenAI API Request]
Estrategia "Blind Extractor":
Le decimos a la IA: "Tus fuentes son exclusivamente las etiquetas XML. El texto en <MANUAL> son las reglas, pero NO puedes copiar texto de ahí. El texto en <AUDIO_REAL> es tu única verdad. Si copias texto que no está en el audio, fallarás."

2.3. ¿Qué es RAG y cómo se usa aquí?

RAG (Retrieval-Augmented Generation) es una técnica que combina un buscador vectorial con un modelo generativo. En Centauro, el modelo NO recibe todo el manual: solo recibe los fragmentos más relevantes recuperados de ChromaDB.

  • Indexación: rag.indexar_documentacion() divide cada manual en chunks de 1000 caracteres.
  • Vectorización: Cada chunk se convierte a embedding y se guarda en .chroma_db/.
  • Consulta: Se hace una búsqueda semántica con un query fijo de "criterios" y se recuperan los top-k fragmentos.
  • Uso en prompt: Los fragmentos recuperados se inyectan dentro de <MANUAL>.

2.4. ¿Qué hace ChromaDB en Centauro?

ChromaDB es la base de datos vectorial local. Se usa como "memoria" del manual, permitiendo recuperar solo la parte relevante sin saturar el prompt.

  • Persistencia: Se guarda en .chroma_db para no recalcular embeddings en cada ejecución.
  • Colección: manual_conocimiento contiene documentos y metadatos (fuente de cada fragmento).
  • Seguridad de consulta: Si no hay manuales, se devuelve un string de fallback y la auditoría continúa.

3. Matriz de Evaluación (Las 6 Fases)

Centauro no evalúa "en general". Divide la llamada en 6 bloques obligatorios. La IA debe rellenar cada bloque, y el código Python (Sheriff) valida la evidencia.

Fase Importancia Lógica de Evaluación (Qué busca el Prompt)
1. INICIO BAJA Busca saludos cordiales ("Hola", "Buenos días", "Soy Paola").
Tolerancia: Si la grabación empieza cortada, no penaliza gravemente.
2. SONDEO ALTA Preguntas Abiertas: Busca interrogantes sobre el perfil, situación laboral o motivación del alumno.
Criterio: Con 1 o 2 preguntas relevantes es suficiente.
3. ARGUMENTACIÓN ALTA Lógica "O" (Inclusiva): No exige todo el manual. Valida si menciona Ranking O Metodología O Online O Partners.
Objetivo: Verificar que aportó valor, independientemente del argumento usado.
4. OBJECIONES / PRECIO ALTA Bolsa de Conceptos Económicos: No busca una cifra fija. Busca palabras como "Inversión", "Euros", "Beca", "Descuento", o cifras variables.
Objetivo: Detectar negociación o explicación de precios, sea cual sea el importe.
5. CIERRE ALTA Siguientes Pasos: Busca compromiso. Palabras clave: "Comité", "Enviar DNI", "Documentación", "Tarjeta", "Pago".
6. LEGAL MEDIA Coincidencia Estricta: Busca raíces de palabras legales: "Grabar", "Calidad", "Monitorizada".
Sheriff: Si no aparecen estas palabras exactas, marca como NO CUMPLE.

4. Metodología de Validación (Sheriff 4.1)

Una vez la IA genera el reporte JSON, entra en acción el script de validación determinista en Python.

Algoritmo "Token Overlap"

El Sheriff no compara frases exactas (que fallan por errores de transcripción como "ehh" o "esteee"). Compara Bolsas de Palabras:

  1. Limpieza: Se eliminan stopwords (el, la, de), puntuación y símbolos de moneda (€, $).
  2. Comparación: Se extraen las palabras clave de la evidencia citada por la IA (ej: ['precio', '5000', 'euros']).
  3. Búsqueda: Se verifica si esas palabras existen en la transcripción original.
  4. Umbral: Si más del 60% de las palabras clave están presentes, se acepta el criterio. Si no, se marca como ALUCINACIÓN.

4.1. Reglas de "Confianza Cero"

  • Si la evidencia viene marcada como NO ENCONTRADO, pasa directo a áreas de mejora.
  • Si la evidencia es demasiado corta o vacía, se marca como error de IA.
  • Se recalcula la nota final en Python con pesos fijos, sin fiarse de la IA.
  • Se separan automáticamente puntos fuertes y áreas de mejora tras la validación.

4.2. Cálculo de Nota Ponderada

La puntuación final no la calcula la IA. Se recalcula con la tabla de pesos en analyze.py:

  • CRITICO: 10 puntos
  • ALTA: 5 puntos
  • MEDIA: 3 puntos
  • BAJA: 1 punto

7. Procesos Internos y Lógica de Datos

7.1 Limpieza de transcripciones

Las transcripciones en VTT se limpian de timestamps y UUIDs. Solo queda el texto conversacional para maximizar la precisión del análisis.

7.2 Redacción de datos personales

Antes de enviar información a la API, se sustituyen patrones sensibles por etiquetas [REDACTED_*] (email, teléfono, DNI/NIE, IBAN).

7.3 Generación del reporte

La IA devuelve un JSON con seis criterios. El Sheriff valida la evidencia y recalcula la nota final en Python. El resultado se guarda en outputs/.

7.4 Control de costes

Todos los consumos se registran en outputs/control_gastos.csv, incluyendo fecha, tokens y coste estimado.

10. Deep Dive: Ingeniería de Prompt (analyze.py)

La IA trabaja en modo "auditor", no como asistente. El prompt limita fuentes y fuerza evidencia literal.

"Eres un AUDITOR DE VENTAS CONSULTIVAS.\nTUS FUENTES:\n1. <MANUAL> {contexto_rag} </MANUAL>\n2. <AUDIO_REAL> (Texto a analizar)\n\nREGLAS:\n- Prohibido inventar texto.\n- Prohibido copiar texto del MANUAL como evidencia.\n- Solo puedes extraer texto literal del AUDIO_REAL.\n\nSALIDA: JSON estricto con 6 fases."

10.1. Estrategia "Dirty Quote Preference"

Se fuerza a la IA a citar incluso errores ("ehh", "esteee") para facilitar la validación tokenizada del Sheriff.

11. Pseudocódigo del Sheriff (Validación)

El Sheriff aplica una comparación tolerante a ruido de transcripción:

def validar_por_tokens(evidencia_ia, texto_real):
    # 1) Limpieza: minúsculas, eliminar moneda y puntuación
    tokens_ia = limpiar(evidencia_ia)
    tokens_real = limpiar(texto_real)

    # 2) Intersección de conjuntos
    aciertos = len(set(tokens_ia) & set(tokens_real))
    ratio = aciertos / len(tokens_ia)

    # 3) Umbral de 60%
    if ratio >= 0.60:
        return True
    return False
