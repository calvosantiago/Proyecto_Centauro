1. Qué Es Centauro

Centauro es un sistema de evaluación automatizada de llamadas comerciales (educación) que analiza conversaciones, etiqueta interlocutores, evalúa bloques consultivos y genera feedback accionable con evidencia literal.

1.1 Objetivo Operativo

  • Evaluar calidad comercial por bloques específicos.
  • Reducir alucinaciones del LLM con validación de evidencias (Sheriff).
  • Aportar recomendaciones accionables apoyadas en manuales, buenas prácticas y coaching.
  • Permitir operación tanto por lotes/CLI como por interfaz interactiva (Chainlit).

1.2 Modos de Uso

  • Modo evaluación (archivo): procesamiento end-to-end de una llamada y generación de JSON/PDF.
  • Modo chat interactivo: preguntas al conocimiento RAG y a memoria de asesores.
  • Modo CLI batch: proceso de múltiples transcripciones desde inputs/transcripts.

3. Entradas, Preproceso Y Flujos (Texto, Audio, Video)

3.1 Entradas soportadas en evaluación

  • .txt
  • .vtt
  • .docx
  • .mp3 (modo web Chainlit)
  • .mp4 (modo web Chainlit)

Validaciones en centauro/utils/validaciones.py:

  • Extensión permitida.
  • Archivo existente y no vacío.
  • Límite de nombre y ruta (Windows), configurable en centauro/config.py.

3.2 Flujo audio

Modo web (app.py / Chainlit): MP3 se transcribe y diariza con AssemblyAI de forma nativa.

  1. Usuario adjunta .mp3 en chat.
  2. Se calcula caché en outputs/transcripciones_cache/ por nombre de archivo.
  3. Si no existe caché, se llama a AssemblyAI con speaker_labels=True, idioma es y modelo universal-3-pro.
  4. Salida estructurada como [Speaker_X]: ... para consumo del DiarizationAgent.
  5. Se registra coste en outputs/control_gastos.csv como transcripcion_assemblyai.
Clave: en flujo web actual, si falta ASSEMBLYAI_API_KEY se lanza error y no se procesa audio/vídeo.
Detalle: el flujo actual documentado usa AssemblyAI como motor de transcripción/diarización para multimedia.

3.3 Flujo video

Modo web: el MP4 se convierte a MP3 temporal con ffmpeg y después pasa por AssemblyAI (mismo flujo que audio).

  1. Colocar videos en inputs/videollamadas.
  2. Ejecutar python centauro/tools/extract_audio.py (requiere C:\ffmpeg\bin\ffmpeg.exe).
  3. Se generan MP3 en inputs/audios.
  4. Procesar en Chainlit (AssemblyAI).

3.4 Privacidad y RGPD

Antes de diarizar/evaluar, redact_pii() reemplaza PII por marcadores [REDACTED_*]:

  • Email
  • Teléfono
  • DNI / NIE
  • IBAN español

3.5 Flujo operativo actual (resumen)

  1. Carga de archivo en Chainlit: .txt, .vtt, .docx, .mp3, .mp4.
  2. Si es multimedia, se convierte a audio cuando aplica y se envía a AssemblyAI con diarización.
  3. Se guarda caché de transcripción en outputs/transcripciones_cache/ para evitar coste repetido.
  4. Se normaliza y protege PII antes de evaluación.
  5. Orquestador ejecuta agentes + Sheriff + síntesis final y persiste resultados.

Señales de calidad (transcript_validator.py)

Señal Umbral Penalización
Palabras totales< 150-0.60
Velocidad (palabras/minuto)< 40 ppm-0.40
Idioma detectadoNo español-0.40
Encoding roto> umbral-0.35
Palabras ininteligibles> 8%-0.30
Sin signos de puntuación—-0.10

Regla de decisión: score ≥ 0.50 → ✅ VÁLIDA · score < 0.50 → ❌ REVISAR.

4. Diarización: Cómo Separa ASESOR Y LEAD

DiarizationAgent resuelve múltiples formatos y aplica estrategia “contenido primero”.

4.1 Detección automática de formato

  • Word pre-diarizado: [NOMBRE]: texto.
  • Formato Teams timestamp: Nombre HH:MM texto.
  • VTT con speakers: <v NOMBRE>texto</v>.
  • VTT con UUIDs.
  • Texto plano sin estructura.

4.2 Asignación de roles

  • Calcula score semántico de asesor/lead por anclas de contenido.
  • Usa coincidencia de nombre solo como respaldo, no como regla principal.
  • Fallback heurístico si el LLM falla o el formato no es concluyente.

4.3 Caso especial VTT UUID

  • Si pocos UUID repetidos: trata UUID como speaker.
  • Si UUID secuencial masivo: diarización batch LLM por chunks con overlap.

4.4 Salida de diarización

Formato normalizado:

[ASESOR]: ...

[LEAD]: ...

Se guarda además copia debug en outputs/Input_Debug/*_diarizada.txt.

6. RAG: Teoría + Implementación En Centauro

6.1 Qué es RAG (contexto teórico)

RAG (Retrieval-Augmented Generation) combina:

  • Retrieval: recuperar conocimiento relevante de una base documental.
  • Generation: usar ese contexto para guiar respuestas/evaluaciones del LLM.

Beneficios clave en Centauro:

  • Reduce respuestas genéricas.
  • Ancla recomendaciones en material interno (manuales, ejemplos, coaching).
  • Mejora consistencia y trazabilidad.

6.2 Base vectorial y colecciones

RAG opera sobre ChromaDB persistente (chroma_db/) con embedding text-embedding-3-small.

ColecciónUsoOrigen
manuales_generalesGuías base de ventainputs/docs/*.txt
buenas_practicasEjemplos reales por bloqueinputs/docs/buenas_practicas/*
coaching_ventasTécnicas de libros/mentoresinputs/docs/coaching_ventas/*.txt
evaluaciones_historicasAprendizaje desde llamadas buenasMemoria continua
dossiers_programasContexto específico de programasoutputs/dossiers_procesados/*.txt
diccionario_datosDiccionario del modelo semántico para consultas @pbiinputs/docs/diccionario_datos/*.txt

6.3 Indexación documental

Entrada recomendada: indexar_si_necesario(). Usa hash de inputs/docs/**/*.txt y solo reindexa si detecta cambios.

  1. Manuales generales (chunking configurable).
  2. Buenas prácticas por sección (indexación completa por ejemplo).
  3. Coaching de ventas con chunking semántico.
  4. Dossiers procesados.
  5. Diccionario de datos del modelo semántico (Power BI).
Operación segura: no es necesario borrar chroma_db/ para reindexar. Si quieres forzar recálculo, borra solo chroma_db/.index_hash o ejecuta una llamada manual a indexar_si_necesario().

6.4 RAG dinámico por bloque

DynamicRAGAgent hace:

  • Extracción de temas de la llamada (muestreo inteligente en llamadas largas).
  • Construcción de query adaptativa según bloque.
  • Recuperación multicolección: manuales + coaching.
  • Filtrado de relevancia y cache de resultados.
flowchart LR A[Transcripción diarizada] --> B[extraer_temas_llamada] B --> C[query dinámica por bloque] C --> D[manuales_generales] C --> E[coaching_ventas] C --> F[buenas_practicas opcional] D --> G[contexto final] E --> G F --> G G --> H[Prompt del agente]

6.5 Parámetros clave (config central)

  • RAG_CHUNK_SIZE=1000
  • RAG_CHUNK_OVERLAP=250
  • RAG_TOP_K_GENERAL=5
  • RAG_TOP_K_BUENAS_PRACTICAS=3
  • RAG_TOP_K_COACHING=2

7. Sheriff Anti-Alucinaciones

_sheriff_validar() valida evidencias citadas por cada bloque contra la transcripción completa.

7.1 Lógica de verificación

  • Valida evidencia principal + extras.
  • Usa fuzzy matching (RapidFuzz) con umbral alto.
  • Calcula porcentaje de evidencias verificables.

7.2 Regla de ajuste de nota

  • Si evidencias verificables < 30%: marca alucinación.
  • Penaliza un nivel de calificación (BUENO→MEJORABLE, MEJORABLE→MALO).
  • Registra metadatos de validación por bloque.

7.3 Telemetría operativa

El orquestador acumula en stats:

  • alucinaciones_detectadas
  • notas_ajustadas_sheriff
  • llamadas_api
  • modo_ejecucion

8.1 Resumen contextual (FASE 2.5)

El sistema extrae de la voz del lead:

  • perfil_lead
  • fase_funnel (AWARENESS, CONSIDERATION, DECISION, CIERRE_INMEDIATO)
  • objetivo_del_lead
  • barreras_principales
  • resultado_general

8.2 Síntesis del reporte

_sintetizar_evaluaciones() consolida:

  • Calificación global por mayoría simple.
  • Feedback resumido con áreas de mejora.
  • Meta técnica (modo batch, distribución de calificaciones, etc.).

9. Chat Interactivo, Memoria Y Aprendizaje Continuo

9.1 Chat Handler (intención + búsqueda)

ChatHandler clasifica intención y enruta a contexto:

  • manual → manuales.
  • ejemplo → buenas prácticas.
  • perfil → perfil histórico de asesor.
  • estadisticas → métricas globales.
  • kpi → modelo semántico Power BI (incluye prefijo forzado @pbi).
  • general → búsqueda multicolección.

9.2 Memoria por asesor

MemoryManager persiste perfiles en Supabase (con fallback operativo si no está disponible):

  • Histórico de evaluaciones.
  • Tendencia (mejorando / estable / empeorando).
  • Fortalezas y áreas de mejora consistentes.
  • Rolling window configurable (180 días).

9.3 Aprendizaje hacia RAG histórico

Evaluaciones con nivel mínimo configurado se pueden indexar en evaluaciones_historicas para alimentar ejemplos futuros.

9.4 Agente @pbi (Power BI)

  • Prefijo @pbi fuerza consulta al modelo semántico.
  • Cliente: centauro/core/powerbi_client.py (REST executeQueries).
  • Agente: centauro/core/pbi_agent.py con OpenAI gpt-5-mini (sin fallback a otro modelo).
  • Comandos directos soportados: @pbi schema, @pbi columnas <tabla>, @pbi EVALUATE ....
  • Timeout de ejecución DAX: 30 segundos por consulta HTTP.

12B. Supabase: Autenticación Y Persistencia SQL

12B.1 Login Chainlit (estado actual)

  • Callback de login: @cl.password_auth_callback en app.py.
  • Validación de credenciales en centauro/auth.py contra tabla usuarios_auth.
  • Hash de contraseñas: pbkdf2:sha256:salt:hash con 260.000 iteraciones.
  • Roles operativos: asesor y admin (alias jefe en script CLI).

12B.2 Tablas SQL principales

Definición en centauro/tools/supabase_schema.sql.

  • usuarios_auth (autenticación Chainlit).
  • asesores (catálogo de asesores y nombre normalizado).
  • evaluaciones (cabecera de evaluación por llamada).
  • calificaciones_bloque (detalle por bloque).
  • oportunidades (cache de datos de lead/oportunidad).

12B.3 Gestión de usuarios (CLI)

Ruta recomendada:

python -m centauro.tools.gestionar_usuarios listar
python -m centauro.tools.gestionar_usuarios crear usuario@dominio.com "Nombre Apellido" Password123 asesor
python -m centauro.tools.gestionar_usuarios cambiar_password usuario@dominio.com NuevaPassword123
python -m centauro.tools.gestionar_usuarios eliminar usuario@dominio.com
python -m centauro.tools.gestionar_usuarios migrar_json

Compatibilidad histórica disponible: python scripts/gestionar_usuarios.py ...

Seguridad: no se puede recuperar la contraseña actual de un usuario; solo resetearla.

12B.4 Persistencia de evaluaciones

  • MemoryManager escribe primero en Supabase si está disponible.
  • Si Supabase no está disponible, la memoria sigue operando con fallback para no bloquear evaluación.
  • El RAG histórico (evaluaciones_historicas) sigue en ChromaDB para aprendizaje.

12C. Integración Power BI / Fabric Y Agente @pbi

12C.1 Flujo de conexión al modelo semántico

  1. Configurar variables en .env: AZURE_CLIENT_ID, AZURE_TENANT_ID, PBI_WORKSPACE_ID, PBI_DATASET_ID.
  2. Ejecutar una vez: python scripts/pbi_auth.py.
  3. El script guarda PBI_REFRESH_TOKEN en .env.
  4. En runtime, PowerBIClient renueva access token automáticamente y ejecuta DAX por REST /executeQueries.

12C.2 Diccionario del modelo semántico (RAG)

  • Fuente principal: inputs/docs/diccionario_datos/diccionario_modelo_semantico.txt.
  • Colección: diccionario_datos en ChromaDB.
  • Fallback si no hay datos: PBI_SCHEMA_HINT en .env.
  • Reindexación: indexar_si_necesario() detecta cambios por hash y reconstruye automáticamente.

12C.3 Uso de comandos en chat

@pbi cuantas entrevistas hubo en marzo 2026
@pbi schema
@pbi columnas H_CUPONES
@pbi EVALUATE ROW("Entrevistas", CALCULATE([CUP_ENT], D_CAL_COM[AÑO-MES] = "2026-03"))
  • @pbi fuerza routing a Power BI.
  • Consultas DAX directas (EVALUATE/DEFINE) se ejecutan en modo sandbox.
  • Timeout actual por consulta DAX: 30 s; si excede, devuelve error de timeout controlado.

14. Diferencias De Versionado Y Componentes Legacy

En el repositorio conviven referencias de versión v3.x, v4.x y v5.x en comentarios y textos de interfaz. El comportamiento real actual observado corresponde a:

  • Arquitectura híbrida + Sheriff + RAG multicolección.

  • Chat interactivo y memoria continua.
Nota técnica importante: esta documentación prioriza el estado funcional del código sobre etiquetas históricas de versión escritas en comentarios antiguos.

15. Glosario

  • RAG: Retrieval-Augmented Generation; recuperación de contexto documental + generación.
  • Sheriff: validador de evidencias literales anti-alucinación.
  • Diarización: separación de hablantes en roles ASESOR/LEAD.
  • Chunk: fragmento de texto en el que se divide un documento para indexarlo o recuperarlo en RAG.
  • Embedding: representación vectorial numérica del texto, usada para medir similitud semántica en la búsqueda.
  • Observabilidad: grado en que un bloque puede evaluarse con evidencia disponible.
  • Batch híbrido: parte de bloques individual, parte en llamada conjunta optimizada.
  • Coaching: fragmentos de libros/técnicas comerciales para recomendaciones.

17.3 Mejoras identificadas

  • Reset de stats["llamadas_api"] entre asesores: el contador se inicializa en __init__ del orquestador y no se resetea entre evaluaciones consecutivas en la misma sesión, produciendo acumulación (14, 28, 42…). Mover la inicialización dentro de evaluar() lo resolvería.
  • Análisis de emoción avanzado: incorporar señales de sentimiento/emoción por utterance como contexto estructurado para EstiloAgent.
  • Runbook unificado CLI/Web: mantener documentación sincronizada para evitar divergencias operativas.
